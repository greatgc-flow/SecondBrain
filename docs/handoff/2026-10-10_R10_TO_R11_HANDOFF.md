## 3. R11 initial TDD slice: evidence-object metadata and cross-links

### Goal

From an **already verified** R7 Capture + R8 Vault publication + R9 local Custody commit, build an idempotent, content-addressed EvidenceObject metadata record and verify the relationships to the actual local payload and distinct capture-specific acquisition/observation records. The feature must fail closed and must **not imply trusted external provenance, final ERL, independent timestamp, WORM, or legal admissibility**.

### Resolve one important semantic tension before writing production code

`profiles/secondbrain/schemas/v2/evidence-object.schema.json` currently **requires `sealed_at`**. Existing `brain_core/verify.py` validates this field, but the present product has **not established a legal/forensic seal**. Preserve backward meaning carefully: choose and document whether `sealed_at` means a narrowly defined *local record publication instant* (and add conspicuous scope/state separation), or replace/extend the draft schema before implementation (for example `recorded_at` + explicit local status), with tests. Never fabricate a trustworthy timestamp or claim external seal to satisfy a schema. Existing v2 design reference should be compared, not blindly adopted.

### Minimum RED oracles

1. Valid **local** record creation uses correct `object_id=obj-sha256-<actual digest>`, SHA-256, SHA-512, byte count, Vault relative path and truthful provenance/status semantics.
2. Already-existing identical metadata is verified rather than overwritten; different metadata at the same object path is an error (**create-if-absent**); no silent `replace()`.
3. Two Capture IDs with identical payload share **one byte object/record** but keep distinct acquisition/custody event pairs and observation identity. Object record must not falsely imply a single acquisition.
4. Missing/not-ready Capture, missing/tampered pending Observation, missing or changed Vault payload, missing/mismatched custody receipt, invalid writer epoch, chain corruption, wrong path/digest/cross-reference, unsafe symlink or JSON duplicate keys are **failures with clear error codes**.
5. Fault-inject before payload/metadata/fsync/publication/receipt and check fail-closed state, no false completion, stable idempotent retry; compare bytes before/after; no overwriting compromised existing objects.
6. Entire root renamed (including Korean/spaces) remains valid; no absolute `SECOND_BRAIN_ROOT` in stored records; no network or paid-provider calls in offline tests.
7. CLI `--help`, JSON output, exit codes and exact user-facing status must match implementation; existing 84 tests continue passing.
8. Candidate-bound CI using actual `rfc8785==0.1.4`; independently check new test cases, final `main` CI after merge.

### Explicit deferred scope (do not silently expand R11)

Independent snapshot/restore and verified secondary backup; OneDrive/Google Drive placeholder/conflict/reparse matrix; multi-device fencing; external WORM/TSA/trusted checkpoint custody; Legal Hold; export production; AI memory/embedding/paid provider canaries; wheel/pip/winget packaging; production release. These follow **after** the smallest R11 slice is correct.

## 4. Workflow and acceptance rules

- **Very Simple / SSOT:** one authoritative code/contract per concern; simple `brain.py` command interface; reusable validation and IO helpers; no bespoke cloud SDK, graph DB, agent orchestration, or duplicate schema interpretations without explicit need.
- **TDD:** save reproducible RED failure, implement minimally, run GREEN locally, run full regression, check source/canonical-data drift; CI evidence must match the exact candidate tree/build.
- **MECE:** normal, boundary, negative, interruption/retry, idempotency, read-only verification, root relocation, privacy, cross-links and operational documentation. Report unsupported environments rather than installing risky workarounds.
- **Feedback:** document discovered defect → root cause / 5 Whys → failing regression → fix → candidate-bound check → operational verification where relevant. Do not close an operational improvement on unit tests alone.
- **Git hygiene:** small branch + PR, no force push to `main`, never erase history, record decisions and test gates. After PR CI succeeds merge normally and verify **new main** CI.
- **Docs:** update `README.md`, scope/quickstart and gate/roadmap; mark unverified assertions explicitly. Prefer links to source and logs over copied counts.
- **Distribution:** GitHub source/PRs/docs only; **no new handoff ZIP** and no formal PyPI/winget release before its gate is met.

## 6. Residual risks / release blockers

1. **External checkpoint custody:** full local ledger replacement can evade purely local validation.
2. **Cloud concurrency:** filesystem O_EXCL / hardlink behavior is not global across cloud-synced multi-PC roots.
3. **Source authenticity:** hashing demonstrates byte consistency, not original truth or lawful acquisition.
4. **TOCTOU / Windows reparse:** existing path guards are not a security proof against concurrent directory replacement.
5. **Partial commit recovery:** write interruption paths tested synthetically; platform/durable-storage guarantees unverified.
6. **Backup:** independent verified secondary snapshot and restore have not been exercised.
7. **Privacy / AI egress:** defaults must remain deny-by-default for source evidence; any live provider tests opt-in, quota/budget bounded, synthetic only.
8. **Distribution:** `pip` wheel tests, system integration, formal release and winget package unverified/unpublished.
