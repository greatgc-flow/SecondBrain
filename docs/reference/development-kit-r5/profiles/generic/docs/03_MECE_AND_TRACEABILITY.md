# 03. 종·횡 MECE 및 양방향 Traceability

## 종: 전체 lifecycle
문제 정의→요구사항→ADR/위험→계약·스키마→RED→GREEN→통합/보안/DR→후보/공급망→배포→관측→사고/RCA→새 요구사항/테스트. 각 단계는 동일 ID·fingerprint·evidence reference를 전달한다.

## 횡: 관심사 분리
1. 가치/범위 2. 구조/소유권 3. 인터페이스 4. 영속성 5. 보안/프라이버시 6. 품질/TDD 7. 공급망/릴리스 8. 운영/개선 9. AI/연동(조건부). 범주 간 상호작용은 `quality/test_catalog.csv` 및 `docs/13_RISK_REGISTER.md`의 교차 반례로 검사한다.

## 검사 규칙
- 요구사항 ↔ 테스트 ID 존재, 중복 없음, Gate G0~G7 유효, 구조 문서에 전건 출력.
- Gate candidate fingerprint가 바뀌면 영향받는 결과 STALE; 서명/실행 이력 없는 PASS는 무효.
- 모든 인수조건에 양성 1/음성 1 이상 존재해야 한다는 것은 *계획 단계 기준*. 실제 시험은 언어별 테스트 코드 작성 및 실행 후 별도 표기.
- 제외/조건부는 근거/승인/재평가 트리거를 남긴다. 불필요한 산출물 생성으로 숫자를 채우지 않는다.
- 비어 있는 실증 구간: 코드·실데이터·실환경·사용성·통합·보안 사고 훈련. 이것을 MECE 완료로 오인 금지.
