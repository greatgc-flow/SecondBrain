# 09. 감사 범위 및 과장 금지

- 패키지의 *정적 설계*는 범용 100, Second Brain 188 원본 요구를 포함한다. 조회용 목록은 원본에서 파생되며 사용자/AI가 `kit catalog`로 정확히 찾는다.
- `kit verify`와 `unittest`의 PASS는 **이 설계 패키지 유틸리티와 문서 계약의 결과**이지 두 제품의 구현·검증 완료가 아니다.
- 개선 기록의 hash chain은 이벤트 사이 국소 변조 감지용이며 외부 신뢰 앵커/신원 인증/분산 transaction을 제공하지 않는다.
- GitHub 커밋 검토는 연결된 **Engram·PeerHub 공개 최근 커밋/릴리스 일부**에 대한 기능 차이 검토다. 이 ZIP의 자체 개발 Git history는 제공되지 않아 완전한 git blame·커밋 누락 검증 불가능. 또한 사용자가 원하지 않은 외부 repo 수정도 하지 않는다.
- 모든 가능한 사용자 시나리오, 모든 전자증거의 법률 증거능력, 모든 도구 버전에서의 경로 호환성은 자동 정적 검사로 증명할 수 없다.
- T3 실제 클라우드 복원, Windows/Node 도구 경계, 보안 침투, T4 provider usage·비용은 미실행. 필수 실증 근거가 없으면 릴리스 `NO-GO`.
- 패키지 root rename/한글/공백 검증은 Python 관리 스크립트에서만 수행한 범위이며, 외부 연동에는 WARN과 T3가 필요하다.
